# 模型故障恢复可靠性升级

## 行为变化
- 流式请求在真正开始消费时读取当前模型健康状态，避免提前创建迭代器后继续使用已熔断的配置。
- 取消的任务不再启动新模型请求；在模型执行期间取消时立即返回上下文错误，不尝试备用模型、不清除已有失败计数。
- 流式响应必须以 message_stop 正常结束。无事件静默结束时，可在安全窗口切换备用模型；已输出文本或工具事件后静默结束，则返回 ErrIncompleteStream，禁止自动重放。
- 部分输出后发生网络或服务故障时，本次仍直接返回错误，并记录到共享熔断器；后续请求可跳过反复失败的端点。
- 参数错误、主动停止消费和取消不再充当成功恢复信号；只有正常完成的调用才能清除健康失败计数。
- 轮询耗尽错误同时保留 ErrExhausted 和原始错误链，便于上层按原因诊断。

## 验证
新增故障模拟覆盖空流、工具事件后的静默断流、重复中途断流、取消前后竞态、请求错误不清空健康、消费时读取健康状态、原始错误链保留及消费者提前停止。无真实模型 API 请求。

    go test -race ./llmpool
    go build ./...

CI 同时执行 report、llmpool、PostgreSQL 导出历史、导出 API 和编译检查。

本轮维持既有重试预算、冷却策略、全配置不可用时的主配置探测行为，不改变任务规划或审批边界。已经交付给上层的部分输出不会在模型池层自动重放；上层任务续跑行为保持现状。
